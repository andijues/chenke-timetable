# 今天安排明天的起床闹钟

在 Android 版「闹钟」选择手机系统时钟，校对课程、设置提前量并开启自动安排。此后打开或返回晨课时，应用按**明天上午第一节已确认课程**发送一次性时钟请求，不再要求每天点击交接或在时钟里保存。默认08:30首课、提前90分钟，对应明早07:00。

实现使用 Android 官方 [AlarmClock.EXTRA_SKIP_UI](https://developer.android.com/reference/android/provider/AlarmClock#EXTRA_SKIP_UI) 请求跳过中间界面。它是一项请求，接收的时钟可能仍显示自己的界面，系统没有提供通用的保存或手动删除回执。因此界面显示「已发送免确认请求」，不冒充「已确认保存成功」。

| 当前情况 | 处理方式 |
| --- | --- |
| 明天有已确认晨课，日期安全 | 应用在前台时自动发送一次 |
| 明天休息、停课或晨课未确认 | 不发送 |
| 今天凌晨，目标钟点还没过去 | 等过了今天该钟点再发送，避免误设成今天 |
| 同一日期、时间和课程已发送 | 保留请求记录，不反复创建 |
| 用户已在时钟手动删除 | 不自动补回同一条，需要时主动重新发送 |
| 课程或提前量已改变，旧请求仍在未来 | 先在时钟删除旧闹钟，再重新发送，避免两个时间都响 |
| 暂停、关闭或切换响铃方式 | 停止后续发送；已经交给系统时钟的闹钟仍需在那里管理 |

「查看或删除闹钟」打开系统时钟列表。「明天暂停自动发送」只影响那一天的自动请求，不删除课程，也不能当作已取消外部时钟的回执。

公共接口只接收时分和重复星期，没有通用的具体日期字段。本项目不发送每周重复参数，只在目标日期等于该时分的下一次实际发生时间时发送。前端负责明日计划筛选，原生端再次核验课程日期与时刻。

Android 对[后台启动界面](https://developer.android.com/guide/components/activities/secure-bal)有限制，不能保证全天不打开晨课仍自动续排系统时钟；这里实现的是应用在前台时自动安排明天。保存到支持接口的系统时钟后，响铃由该时钟负责，实际锁屏表现需在设备上测试。

本机鸿蒙7的卓易通此前未提供创建系统时钟的接口。改变免确认参数不会补出缺失接口，增加晨课自己的通知或准确闹钟权限也不会改变这个结果。原生鸿蒙的系统代理提醒是另一条调度路径，需要相应能力和签名；不会强行写入华为时钟列表。
