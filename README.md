# 晨课 · 个人课表

一个零付费服务、无服务器的个人课表项目。共享界面、Android 与鸿蒙原生工程均为 0.3.2。本轮将蓝白色设计完善到导入校对、闹钟、设置、备份和课程编辑。设置采用五类标签页，节次精确表格按需展开，校对操作独立成行；今日首页及 Android 明日时钟自动请求保持原有逻辑。鸿蒙只生成未签名 HAP，等待代理提醒审批后再更新签名；本轮不自动安装到手机。本项目仅维护 Android 与鸿蒙。

本机鸿蒙 7 的卓易通实测：Android 0.2.3 退出后台后不响；0.2.4 的系统时钟接口调用失败。原生鸿蒙采用系统代理提醒路径。最近一次华为后台检查（2026-10-15）仍为审核中，本轮未再次查询、未更新 Profile 或签名，也没有运行手机安装命令。

开发环境为 Windows，维护鸿蒙 7 原生版与 Android 版；电脑网页仅用于课表预览。

## 已实现

- 文字 PDF、扫描 PDF、PNG/JPG 图片在本机识别；中文/英文 OCR 模型随项目打包。
- 表格按真实边界、星期列和时间/节次分组；支持合并格、同列跨页续接、换行名称、单双周与离散周次。侧转扫描/轮廓字 PDF 自动校正方向并逐格识别；每项保留原文和教室，导入后需核对确认。
- 课表含具体时刻时优先使用原表时间；只有节次时明确提示核对学校作息。同课相邻节只有周次与地点完全一致才合并，未排定时间的页尾课程不会擅自排课或生成闹钟。
- 首页可直接手动添加课程，按节次选择或精确填写时间；课程编辑器统一白色表单、分组、固定标题和保存栏。
- 设置按学期、节次、课程、调课、备份分类，支持键盘切换，切换时保留未保存输入。
- 学期首日不限星期一，自动显示第1周对应周一；支持起止周、每周/单周/双周、逐周点选及实际日期预览。
- 通用节次及每天独立设置，星期独立设置允许0–20节；时间轴、滑块及精确输入共同编辑。按节次录入的课程和起床计划联动更新。
- 默认今日课程，突出下一节课、地点、课程进度与明日起床；支持完整周课表、当前时间指针、浅色/暗色、手机底栏与桌面侧栏。
- 取当日第一门晨课，减可调提前量。默认 90 分钟、上午截止 12:00，均可修改；支持跨天提前。
- 停课/假日、按其他星期调课、学期起点与总周数、学校节次表、时间冲突提示、JSON 备份恢复、课程日历导出。
- 鸿蒙：系统后台代理提醒；Android 默认尝试交给系统时钟，保留晨课后台提醒作为可选方式。
- 原生提醒窗口 28 天；Android 时钟模式只为明天发送一次性请求，并请求跳过确认页面。应用在前台时自动发送，同一计划不重复创建；手动删除后不自动补回，修改时间后先删除旧闹钟再重新发送。关闭、暂停、切换方式或清空课表后持续保留外部时钟管理提示。未确认晨课、休息日、演示数据不发布闹钟。

## 立即预览

安装了 Node.js 后，在本目录运行：

```powershell
npm.cmd ci
npm.cmd run assets
npm.cmd run build
npm.cmd run preview
```

打开 <http://127.0.0.1:5173/>，或者双击 `启动预览.cmd`。运行窗口只用于电脑本地预览，手机原生版会将界面直接打包在应用里。

首次进入是空课表；可选择「先体验演示课表」，不会设置闹钟。要开始真实记录，选择「开始自己的课表」并导入。

先在「设置」填写学校学期第一天、总周数及节次，再导入和校对课程；也可从首页直接手动排课。默认日期不能代替学校校历。

### 开发与校验

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run assets
npm.cmd run build
npm.cmd test
npm.cmd run test:harmony
npm.cmd run test:ui
```

`test:harmony` 需要 Node.js 24，执行实际 ArkTS 桥接源码并以模拟系统服务验证授权、提醒替换和取消；不等于真机响铃验收。依赖采用 package-lock.json 固定版本。`assets` 仅构建时从开源项目下载中文/英文 OCR 模型，应用运行不调用识别服务。`build` 把 dist 复制到 Android 与鸿蒙两个原生工程。UI 测试使用 Windows Edge，实际上传匿名 PDF/图片并执行本机 OCR；个人原课表不进入仓库或交付归档。

## Android 安装与构建

Android 0.3.2 输出为 output/晨课-Android-调试.apk；实现官方 AlarmClock 免确认请求、明日一次性计划、1–2 分钟测试和列表入口。本机卓易通未提供该接口，实际调用失败；其他 Android 手机需独立验证。接口没有通用指定日期字段，不能直接自动同步单双周或整个学期，只在明日目标时刻等于该时分的下一次实际发生时间时自动发送；全天不打开应用不保证续排。详见[系统时钟自动安排](docs/系统时钟自动安排.md)。APK 最低 Android 8.0，目标 API 36。详细步骤见 [Windows 构建和使用安卓](docs/Windows安装安卓.md)。

## 鸿蒙 7 安装

鸿蒙工程为 0.3.2，目标 API 26、最低 API 20，包名 `com.andijues.chenke`。本机官方工具位于 `D:\command-line-tools`。本轮只生成新版未签名 HAP；`output/晨课-鸿蒙-已签名.hap` 仍是旧版 0.2.0，不能当作本轮交付。等待代理提醒能力获准后再下载 Profile、更新签名；本轮不安装。

完整步骤和命令见 [Windows 构建与安装鸿蒙版](docs/Windows安装鸿蒙.md)。

1. 准备官方 Command Line Tools 26.0.0.851 和 JDK 17；此命令行工具包未自带 JDK。
2. 使用 `scripts/build-harmony.mjs --tools ... --java ... --stage ...` 在独立目录编译，再使用 `scripts/verify-harmony-artifact.py` 检查内容。
3. 通过实名认证华为开发者账号创建匹配包名的调试证书、自己的设备记录与 Profile。私钥和密码保存在项目外。
4. 使用 `scripts/sign-harmony.mjs` 核对证书、单设备 Profile 后签名，以官方 HDC 覆盖安装。也可按官方 DevEco Studio 自动签名流程操作。
5. 在应用中导入课表、校对晨课、启用自动提醒，并允许通知。
6. 先执行「测试 1 分钟后响铃」，检查锁屏、声音、稍后提醒、退出应用、重启后的行为。签名有效期以实际平台为准。

这里的提醒由应用通过系统代理管理，**不等于往华为“时钟”App 的手动闹钟列表写入**。响铃的通知/闹钟通道表现必须在鸿蒙 7 真机上确认。按日期使用 Calendar 类型，避免把课程简单设成每周重复后在放假日误响。

本次真机测试返回1700002，而晨课有效提醒数量为0；后台“代理提醒”能力原为“未申请”，Profile 中该开放能力为空。现已授权提交申请，平台显示“审核中”，页面提示审批3个工作日；获准后需取得对应 Profile 并重新签名。资料见 [代理提醒申请说明](docs/鸿蒙代理提醒申请.md)。不应因此删除手机其他应用或时钟的闹钟。

## 实际使用边界

- 已在本机对照两份实际课表逐项检查；通用回归采用独立编写的匿名样本，见[课表识别与校对](docs/课表识别与校对.md)。这不代表所有学校版式或图片都能准确识别。
- OCR 永远需要校对，不保证图片全部识别正确；原文保留供手动补充。未找到时间会明确标记，不能默默把推算当作准确结果。
- 所有课程按中国标准时间 UTC+8 解释。旅行或系统时区调整后需重新打开并检查起床计划。
- 原生提醒窗口为未来 28 天，定期打开应用续排；Android 系统时钟仅在前台为明日自动请求，系统仍可能显示自己的界面，没有通用保存或删除回执。手机关机、权限撤销、系统限制和签名过期均需要真机验证和处理。
- 当前无云账号体系、自动跨设备同步、收费接口；可以用 JSON 备份转移数据。

## 项目文件

`src/` 为规则、解析、界面和原生桥接；`native/harmony/` 和 `native/android/` 为原生工程；`dist/` 为已构建预览；`tests/fixtures/` 为带演示标记的文字/扫描 PDF 与图片。`reports/` 为检查记录，`.impeccable/review/` 为网页截图。
